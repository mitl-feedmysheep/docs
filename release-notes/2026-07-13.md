# 2026-07-13

## 백엔드 (backend)

**리딩플랜 아이콘 미노출 버그 수정 (타임존)**
- 증상: 관리자가 리딩플랜 시작일을 7/13로 활성화했는데, 자정~오전 9시(KST) 사이에는 웹앱에 리딩플랜 아이콘이 뜨지 않음
- 원인: `ReadingPlanQueryService`, `ReadingCompletionCommandService`, `ReadingPlanPersistenceAdapter`, `ReadingPlanController`가 타임존 없이 `LocalDate.now()` / `LocalDateTime.now()`를 호출 → 컨테이너 기본 timezone(UTC) 기준으로 "오늘"이 계산되어 KST 자정~09:00 사이에는 실제로 하루 전 날짜로 인식됨. `start_date`가 오늘인 플랜이 "아직 시작 안 함"으로 판정되어 `isReadingEnabled()`가 false 반환
  - 7/10에 `DailyReadingPushScheduler`에서 동일한 버그를 `LocalDate.now(Asia/Seoul)`로 수정한 적이 있었으나, 같은 기능의 나머지 클래스들에는 적용되지 않았던 것으로 보임
- 수정: 위 4개 클래스에 `private static final ZoneId KST = ZoneId.of("Asia/Seoul")`를 추가하고 모든 `LocalDate.now()` / `LocalDateTime.now()` 호출을 `LocalDate.now(KST)` / `LocalDateTime.now(KST)`로 명시
- 컨테이너/JVM 기본 timezone(Dockerfile `TZ` 등)은 건드리지 않음 — 다른 도메인(생일 조회 등)에서 이미 `LocalDate.now()`를 UTC 기준으로 쓰는 코드가 다수 있어(`ChurchPersistenceAdapter`, `DepartmentPersistenceAdapter`, `Prayer`, `Visit`, `SermonNote` 등), 전역 기본값을 바꾸면 그쪽에 새로운 회귀를 일으킬 위험이 있음. 리딩플랜 관련 클래스만 명시적으로 타임존을 고정하는 범위로 수정

**공지사항 발송예약 스케줄러의 "오늘" 판정 타임존 고정**
- `AnnouncementPushScheduler.java`의 `LocalDateTime.now()`를 명시적 `ZoneOffset.UTC`로 고정 (`send_at`이 `hibernate.jdbc.time_zone=UTC`로 UTC 인스턴트가 그대로 저장되므로, KST로 바꾸면 오히려 9시간 일찍 발송되는 반대 방향 버그가 생김 — admin 쪽 발송예약 버그 수정과 짝을 이루는 변경, 아래 admin 섹션 참고)

**설교노트 설교자 필드 이력 조회용 엔드포인트 추가**

**버그접수(Report) 자가접수 시 알림 누락 수정**
- 증상: 관리자 본인이 리포트를 접수해도 알림이 오지 않음
- 원인: `ReportCommandService.create()`가 `if (!isSystemAdmin(reporterId))`로 감싸져 있어, 리포트 수신자가 항상 고정된 관리자 계정임에도 접수자가 관리자 본인이면 알림 생성 자체를 건너뜀 (`addComment`의 셀프케이스 스킵 로직이 잘못 복사된 것으로 보임 — `addComment`는 상대방이 실제로 발신자와 같을 때만 스킵하는 반면, `create`는 수신자가 항상 고정값이라 이 가드가 성립하지 않음)

## admin

**공지사항 발송예약 시간이 9시간 밀려서 저장되는 버그 수정 (타임존)**
- 증상: 발송예약을 15:00으로 설정하면 실제로는 다음날 00:00으로 저장됨
- 원인: 프론트가 타임존 없는 `YYYY-MM-DDTHH:mm:00` 문자열을 만들어 보내고, API가 `new Date(sendAt)`으로 파싱 — 서버 프로세스 기본 타임존(UTC)으로 해석되어 KST→UTC 변환이 누락됨. 같은 패턴이 주보 발송예약(`bulletin-manage-client.tsx`)과 심방 시작/종료 시각(`visit-manage-client.tsx`)에도 동일하게 있었음
- 수정: `admin/src/lib/datetime.ts` 공용 유틸(`buildKstIso`, `formatKstDateTime`, `formatKstDate`, `formatKstTime`, `todayKstDateString`, `kstDayRangeUtc`) 신설, 위 3곳의 빌드 로직과 표시 포맷을 전부 이 유틸로 교체. `app/api/departments/[id]/reading-plan/{progress,weekly-group-progress}` 라우트의 "오늘" 계산도 서버 로컬 타임존 의존(`new Date()` + `setHours`)에서 KST 고정으로 교체
- 상세 배경/결정 이유: `docs/plans/2026-07-13-kst-datetime-utility.md`
