# 2026-07-13

## 백엔드 (backend)

**리딩플랜 아이콘 미노출 버그 수정 (타임존)**
- 증상: 관리자가 리딩플랜 시작일을 7/13로 활성화했는데, 자정~오전 9시(KST) 사이에는 웹앱에 리딩플랜 아이콘이 뜨지 않음
- 원인: `ReadingPlanQueryService`, `ReadingCompletionCommandService`, `ReadingPlanPersistenceAdapter`, `ReadingPlanController`가 타임존 없이 `LocalDate.now()` / `LocalDateTime.now()`를 호출 → 컨테이너 기본 timezone(UTC) 기준으로 "오늘"이 계산되어 KST 자정~09:00 사이에는 실제로 하루 전 날짜로 인식됨. `start_date`가 오늘인 플랜이 "아직 시작 안 함"으로 판정되어 `isReadingEnabled()`가 false 반환
  - 7/10에 `DailyReadingPushScheduler`에서 동일한 버그를 `LocalDate.now(Asia/Seoul)`로 수정한 적이 있었으나, 같은 기능의 나머지 클래스들에는 적용되지 않았던 것으로 보임
- 수정: 위 4개 클래스에 `private static final ZoneId KST = ZoneId.of("Asia/Seoul")`를 추가하고 모든 `LocalDate.now()` / `LocalDateTime.now()` 호출을 `LocalDate.now(KST)` / `LocalDateTime.now(KST)`로 명시
- 컨테이너/JVM 기본 timezone(Dockerfile `TZ` 등)은 건드리지 않음 — 다른 도메인(생일 조회 등)에서 이미 `LocalDate.now()`를 UTC 기준으로 쓰는 코드가 다수 있어(`ChurchPersistenceAdapter`, `DepartmentPersistenceAdapter`, `Prayer`, `Visit`, `SermonNote` 등), 전역 기본값을 바꾸면 그쪽에 새로운 회귀를 일으킬 위험이 있음. 리딩플랜 관련 클래스만 명시적으로 타임존을 고정하는 범위로 수정
