# 소모임 코멘트 상호 알림

## 개요

소모임(Gathering)의 리더 코멘트 ↔ 목회자 코멘트가 서로에게 인앱 알림 + 웹푸시로 전달되지 않던 비대칭을 해소한다.

- 기존: 목회자 코멘트(adminComment) 변경 시에만 리더에게 인앱 알림(푸시 없음)이 감. 리더 코멘트(leaderComment) 변경 시엔 아무 알림도 안 감.
- 변경 후: 양방향 모두 인앱 알림 + 웹푸시 발송.

## 배경 / 제약

- Group의 리더는 1명이지만, Department의 ADMIN(목회자)은 여러 명일 수 있음. `DepartmentRole`은 `MEMBER/LEADER/ADMIN` 세 단계뿐이며 `SUPER_ADMIN`은 `ChurchRole`에만 존재.
- 리더 코멘트는 web-app → 백엔드 Java API(`PATCH /gatherings/{id}`)로 저장되므로, 알림+푸시를 같은 트랜잭션 안에서 동기 처리 가능.
- 목회자 코멘트는 admin(Next.js) → Prisma로 DB 직접 저장. admin은 VAPID 웹푸시 인프라가 없었음.
  - 대안으로 backend가 폴링(예: `AnnouncementPushScheduler`처럼 5분 주기)하는 방식도 검토했으나, admin에 웹푸시 발송 기능 자체를 만들어 지연 없이 즉시 발송하고 향후 admin의 다른 기능(공지 즉시발송 등)에도 재사용하는 방향으로 결정.

## 구현

### Backend (리더 코멘트 → Department ADMIN)

- `NotificationType`에 `LEADER_COMMENT` 추가 (`domain/enums/NotificationType.java`)
- `GatheringCommandService.updateGathering()`에 `leaderComment` 변경 감지 블록 추가
  - `DepartmentPort.findAdminsByDepartmentId()`로 해당 그룹 부서의 ADMIN 전원 조회 (기존 `ChurchCommandService.notifyAdmins`와 동일 패턴)
  - 미읽음 중복 알림 체크(`notificationPort.existsUnreadByReceiverAndTypeAndEntity`) 후 `Notification` 저장
  - `PushSubscriptionPort` + `WebPushPort`로 웹푸시 발송, GONE/INVALID 응답 시 구독 삭제 (기존 `ReportCommandService`/`ChurchCommandService` 패턴 재사용)
  - 테스트: `GatheringCommandServiceTest`에 `LeaderCommentNotificationTests` 추가

### Admin (목회자 코멘트 → 소모임 리더)

- `push_subscription` 테이블을 Prisma 스키마에 신규 매핑 (`admin/prisma/schema.prisma`) — backend가 쓰는 동일 MySQL 테이블, FK 관계 없음(원본 JPA 엔티티도 관계 없이 순수 컬럼)
- `web-push` npm 패키지 추가, `admin/src/lib/webpush.ts` 신설
  - `sendPushToMembers(memberIds, payload)`: VAPID 키로 발송, 404/410/403 응답 시 `push_subscription` row 삭제 (backend `WebPushAdapter`와 동일 규칙)
- `admin/src/app/api/dashboard/gatherings/[id]/route.ts` PATCH: 기존 인앱 알림 생성 로직 뒤에 `sendPushToMembers` 호출 추가 (알림이 실제로 새로 생성된 리더에게만 발송)
- 테스트: `route.test.ts` 신규 작성 (401/404/변경없음/변경/중복알림 스킵 케이스)

## 환경변수

admin에 아래 3개 추가 필요 (backend가 이미 쓰는 것과 **동일한 값**을 그대로 사용해야 구독자 브라우저가 유효한 발신자로 인식함):

- `WEBPUSH_VAPID_PUBLIC_KEY`
- `WEBPUSH_VAPID_PRIVATE_KEY`
- `WEBPUSH_VAPID_SUBJECT`

**→ Doppler에서 admin 프로젝트에 위 3개 환경변수를 backend와 동일한 값으로 추가해주세요.**
