# 리딩지저스 (Daily Bible Reading) 기능 설계

## 왜 만드는가

부서 단위로 운영하는 매일 성경 통독 기능. 현재는 각 소그룹 리더가 카톡방을 따로 만들어
매일 읽을 범위 + 유튜브 링크 + 요약 사진을 올리고, 멤버가 "완독" 댓글을 달면 리더가
수동으로 진도율을 집계하는 방식. 리더 부담이 크고 데이터도 카톡에 분산된다.

이를 앱 안으로 가져와 자동화한다.

## 목표

- 전체 통독 계획(범위/유튜브/사진)을 한 번 일괄 등록하면 매일 그날 분량을 멤버에게 노출
- 멤버가 앱에서 완독 체크 → 개인 진도율(전체 계획 분량 대비 %) 자동 계산
- 어드민에서 부서 전체 진도율 + 개인별 진도 확인
- 아침마다 오늘의 리딩지저스 푸시 발송 (미완독자에게만)
- 기능 자체는 특정 교회/부서에 한정

## 도메인 설계

### 핵심 결정: ReadingPlan은 독립적, 부서 매핑은 별도 테이블

`ReadingPlan`(통독 계획 컨텐츠)은 특정 부서에 종속되지 않는다.
어느 부서에서 이 플랜을 사용하는지는 `DepartmentReadingPlan` 매핑 테이블로 관리한다.

이유:
- 동일 플랜을 여러 부서에서 재사용 가능 (예: 같은 교회의 청년부/신혼부부부가 같은 계획 사용)
- 활성화/비활성화가 `department` 테이블 수정 없이 매핑 행 생성/삭제로 처리
- `department`가 읽기 기능 관련 플래그로 오염되지 않음
- 나중에 다른 부서로 플랜을 복제/이관할 때 유연

### 엔티티 구조

```
ReadingPlan (플랜 컨텐츠, 부서 무관)
├── id, title, start_date, total_days (진도율 분모)
│
├── ReadingPlanDay (하루치 분량, N개)
│   ├── id, reading_plan_id FK
│   ├── reading_date (DATE — 오늘 분량 조회 키)
│   ├── day_number
│   ├── reading_range (예: "창세기 1-3장")
│   ├── youtube_url (String — 외부 링크, 단순 컬럼)
│   ├── description (요약 텍스트, nullable)
│   └── Media[] (요약 사진, entity_type='READING' 다형성 첨부)
│
└── DepartmentReadingPlan (부서-플랜 매핑 테이블)
    ├── id, department_id FK, reading_plan_id FK
    ├── is_active (해당 부서의 현재 활성 플랜, 부서당 1개)
    └── deleted_at (soft delete — 비활성화는 행 삭제 또는 is_active=false)

ReadingCompletion (멤버×하루 완독 기록)
├── id, reading_plan_day_id FK, member_id FK
├── completed_at
└── hard delete (education_progress와 동일 이유: 토글 시 unique 충돌 회피)
```

### 인덱스 계획

| 테이블 | 인덱스 |
|--------|--------|
| `reading_plan_day` | `(reading_plan_id, reading_date)` |
| `department_reading_plan` | `(department_id, is_active)`, `(reading_plan_id)` |
| `reading_completion` | `(reading_plan_day_id, member_id)` unique, `(member_id)` |

### Media 연동

기존 다형성 패턴 재사용. `EntityType` enum에 `READING` 추가.
`ReadingPlanDayJpaEntity`에 `@SQLRestriction("entity_type = 'READING'")` 적용
(`GroupJpaEntity.java:78-88` 패턴 복사).

## 스키마 DDL (백엔드가 소유, 수동 적용)

```sql
-- ReadingPlan
CREATE TABLE reading_plan (
    id          CHAR(36)     NOT NULL COMMENT '플랜 UUID',
    title       VARCHAR(100) NOT NULL COMMENT '플랜 제목 (예: 2026 창세기 통독)',
    start_date  DATE         NOT NULL COMMENT '플랜 시작일',
    total_days  INT          NOT NULL COMMENT '전체 일수 (진도율 분모)',
    created_at  DATETIME(6)  NOT NULL COMMENT '생성일시',
    updated_at  DATETIME(6)  NOT NULL COMMENT '수정일시',
    deleted_at  DATETIME(6)           COMMENT 'soft delete',
    PRIMARY KEY (id)
) COMMENT = '통독 계획';

-- ReadingPlanDay
CREATE TABLE reading_plan_day (
    id              CHAR(36)     NOT NULL COMMENT '하루 분량 UUID',
    reading_plan_id CHAR(36)     NOT NULL COMMENT '상위 플랜 ID',
    reading_date    DATE         NOT NULL COMMENT '해당 날짜',
    day_number      INT          NOT NULL COMMENT '플랜 내 순서',
    reading_range   VARCHAR(200) NOT NULL COMMENT '읽기 범위 (예: 창세기 1-3장)',
    youtube_url     VARCHAR(500)          COMMENT '유튜브 링크',
    description     TEXT                  COMMENT '요약 텍스트',
    created_at      DATETIME(6)  NOT NULL COMMENT '생성일시',
    updated_at      DATETIME(6)  NOT NULL COMMENT '수정일시',
    deleted_at      DATETIME(6)           COMMENT 'soft delete',
    PRIMARY KEY (id),
    INDEX idx_reading_plan_day_plan_date (reading_plan_id, reading_date)
) COMMENT = '통독 계획 하루 분량';

-- DepartmentReadingPlan (매핑 테이블)
CREATE TABLE department_reading_plan (
    id              CHAR(36)    NOT NULL COMMENT '매핑 UUID',
    department_id   CHAR(36)    NOT NULL COMMENT '부서 ID',
    reading_plan_id CHAR(36)    NOT NULL COMMENT '플랜 ID',
    is_active       TINYINT(1)  NOT NULL DEFAULT 1 COMMENT '활성 여부 (부서당 1개만 활성)',
    created_at      DATETIME(6) NOT NULL COMMENT '생성일시',
    updated_at      DATETIME(6) NOT NULL COMMENT '수정일시',
    deleted_at      DATETIME(6)          COMMENT 'soft delete',
    PRIMARY KEY (id),
    INDEX idx_dept_reading_plan_dept_active (department_id, is_active),
    INDEX idx_dept_reading_plan_plan (reading_plan_id)
) COMMENT = '부서-통독 플랜 매핑';

-- ReadingCompletion (hard delete)
CREATE TABLE reading_completion (
    id                  CHAR(36)    NOT NULL COMMENT '완독 기록 UUID',
    reading_plan_day_id CHAR(36)    NOT NULL COMMENT '해당 날짜 분량 ID',
    member_id           CHAR(36)    NOT NULL COMMENT '완독한 회원 ID',
    completed_at        DATETIME(6) NOT NULL COMMENT '완독 일시',
    PRIMARY KEY (id),
    UNIQUE KEY uq_reading_completion_day_member (reading_plan_day_id, member_id),
    INDEX idx_reading_completion_member (member_id)
) COMMENT = '멤버 완독 기록';
```

### REST 엔드포인트

멤버용 (web-app 소비):
```
GET  /departments/{departmentId}/reading-plan/today
     → 오늘 분량 + 내 완독 여부 + 활성화 상태

GET  /departments/{departmentId}/reading-plan/days
     → 전체 일자 목록 (캘린더/지난날 보충용)

POST /reading-plan-days/{dayId}/completion    — 완독 체크
DELETE /reading-plan-days/{dayId}/completion  — 완독 취소

GET  /departments/{departmentId}/reading-plan/me/progress
     → 완독수, 총일수, 진도율%, streak, 완독 날짜 목록
```

관리자/리더용:
```
GET  /departments/{departmentId}/reading-plan/progress
     → 부서 전체 집계  @RequireDepartmentRole(LEADER)

GET  /departments/{departmentId}/reading-plan/members/{memberId}/progress
     → 개인 상세  @RequireDepartmentRole(LEADER)

POST /reading-plans                   — 플랜 생성  @RequireDepartmentRole(ADMIN)
POST /reading-plans/{planId}/days/batch — 일자 일괄 등록
POST /departments/{departmentId}/reading-plan/activate — 매핑 생성(플랜 활성화)
DELETE /departments/{departmentId}/reading-plan       — 매핑 삭제(비활성화)
```

권한: `/departments/{departmentId}/...` 경로에 `@RequireDepartmentRole` aspect가 자동 적용
(`departmentId` path variable 필수).

### 진도율 계산

```
진도율(%) = (ReadingCompletion 개수) / (ReadingPlan.total_days) × 100
```

## 아침 푸시 (기존 인프라 재사용)

신규 환경변수 없음. 기존 VAPID 설정/스케줄러 그대로 재사용.

`global/scheduler/DailyReadingPushScheduler.java`:
- `AnnouncementPushScheduler` 패턴 복사
- `@ConditionalOnProperty(webpush.scheduler.enabled, matchIfMissing=true)`
- 실행: 매시 실행 + timezone 필터로 멤버 로컬 7시에 발송 (`HourlyPrayerPushScheduler` 패턴)
- 대상: `DepartmentReadingPlan`에 활성 플랜이 있는 부서의 ACTIVE 멤버 중 **오늘 미완독자**만
- payload: `{title:"오늘의 리딩지저스", body: 오늘 읽기 범위, url:"/reading"}`
- `webPushPort.send(...)`, GONE/INVALID 구독 자동 삭제

`public/sw.js`: 기존 `tag:"mitl-daily-prayer"`와 겹치지 않게 리딩지저스 전용 `tag` 추가.

- 읽기 범위, 요약 설명, 요약 사진(`<img src crossOrigin="anonymous">`)

### API 추가 (`src/lib/api.ts`)

```ts
export const readingApi = {
  getToday: (departmentId: string) =>
    authedFetch<TodayReading>(`/departments/${departmentId}/reading-plan/today`),
  markComplete: (dayId: string) =>
    authedFetch<void>(`/reading-plan-days/${dayId}/completion`, { method: "POST" }),
  unmarkComplete: (dayId: string) =>
    authedFetch<void>(`/reading-plan-days/${dayId}/completion`, { method: "DELETE" }),
  getMyProgress: (departmentId: string) =>
    authedFetch<ReadingProgress>(`/departments/${departmentId}/reading-plan/me/progress`),
  getDays: (departmentId: string) =>
    authedFetch<ReadingPlanDay[]>(`/departments/${departmentId}/reading-plan/days`),
};
```

타입은 `src/types/index.ts`에 추가.

### 라우팅 & 진입점

- `src/App.tsx`에 `/reading`, `/reading/progress` 라우트 추가 (ProtectedRoute 하위)
- BottomNav는 이미 5탭이므로 6번째 탭 대신 **홈 화면 진입 버튼**으로 처리
