# 나의 기도 + 기도 알림 개편

## 배경

- 일반 멤버는 모임 기도제목을 직접 쓸 수 없어(리더/부리더만 편집) 앱을 열 이유가 적다
- 매일 9시 기도 알림은 고정 제목("오늘도 기도로 하루를 열어요 🙏"), 본문 없음, 홈(`/`)으로 이동 → 눌러도 볼 게 없어 클릭되지 않음
- 기도 알림 ON 22명 중 최근 7일 내 기도제목이 있는 사람은 12명 → 기도제목이 없는 사람용 알림도 매일 같은 문구가 되지 않게 해야 함

선행 작업: `2026-11-26-push-analytics.md` (문구 로테이션이 `push_delivery_log`를 사용)

## 1. 나의 기도 (모임과 무관한 개인 기도제목)

### 데이터

신규 테이블 없음. `prayer`에서 `gathering_member_id IS NULL AND visit_member_id IS NULL`인 행이 "나의 기도".
도메인상 이미 개인 컨텍스트가 정의되어 있고, `/prayers/me` 조회도 이미 포함함 (현재 1건 존재).

- 응답 체크 전까지 계속 유지 (주 단위로 바뀌지 않음)
- **본인만 열람** — 리더/관리자 비공개

### 백엔드

- `POST /prayers` — 나의 기도 작성 (`prayerRequest` 필수, 200자 제한 = 기존 컬럼)
- `PATCH /prayers/{id}` — 내용 수정 (본인 + 나의 기도만)
- 기존 `PATCH /{id}/answered`, `DELETE /{id}` 재사용 (본인 검증 확인)
- `/prayers/me` 응답에 `source: "MY" | "GATHERING"` 추가
- 홈 요약(`HomeSummaryResponse`)에 `myPrayers` 추가 (미응답, 최근순 최대 3개 + 총 개수)

### 비공개 처리 (기존 쿼리 점검)

나의 기도가 다른 사람에게 노출되지 않도록 `member_id` 기준으로 기도제목을 조회하는 곳에 개인 기도 제외 조건 추가:
- admin `api/members/[id]/route.ts`, `members/[id]/page.tsx` (회원 상세 기도제목 히스토리)
- admin `api/prayers/route.ts`, `api/system/monitoring/route.ts` (집계 — 개인 기도 포함 여부 구현 시 확인)
- backend `PrayerPersistenceAdapter.findPrayerRequestCountByMemberIds` 등 그룹/부서 단위 집계

### 웹앱

**기도 탭 (`PrayerPage`)**
- 헤더 우측 `+ 직접 쓰기` 버튼 → 작성 시트 (작성/수정 공용)
- 목록 상단에 "📌 내가 쓴 기도제목" 그룹, 그 아래 기존 모임 날짜별 그룹
- 출처 라벨: 나의 기도 `나의 기도 · 11월 20일`, 모임 기도 `{소그룹 이름} · 11월 23일 모임` (기존 그대로)
- 기존 상태 필터(전체/기도 중/응답됨) 유지

**홈**

`나의 한 주` 카드 위에 `나의 기도` 섹션 신설.

```
┌───────────────────────────────┐
│ 🙏 나의 기도               +  │
│ • 부모님 건강이 회복되도록      │
│ • 매일 말씀 읽는 습관           │
│ • 동생이 교회에 다시 나오도록   │
│                      전체보기 › │
└───────────────────────────────┘
┌───────────────────────────────┐
│ 나의 한 주        11/23 - 11/29│
│ 🎯 한주 목표                   │
│  • 매일 큐티하기               │
│ 🙌 모임 기도제목               │
│  • 이직 준비 중인데 지혜로운     │
│    선택을 할 수 있도록  김성민셀 │
└───────────────────────────────┘
```

표시 규칙:

| 나의 기도 | 이번 주 모임 기도제목/목표 | 홈 표시 |
|---|---|---|
| 있음 | 있음 | 나의 기도 + 나의 한 주 |
| 있음 | 없음 | 나의 기도만 |
| 없음 | 있음 | 나의 한 주만 (나의 기도 섹션 숨김) |
| 없음 | 없음 | "적어볼까요" 빈 카드만 |

빈 카드:
```
┌───────────────────────────────┐
│ 🙏 나의 기도                   │
│  마음에 있는 기도제목을          │
│  하나 적어볼까요?               │
│       [ ✍️ 기도제목 쓰기 ]      │
└───────────────────────────────┘
```

- 섹션이 출처를 구분하므로 같은 내용이 위아래에 있어도 중복 제거하지 않음
- 모임 기도제목 옆 라벨은 **소그룹 이름**

## 2. 기도 알림 개편

### 알림 내용 결정 로직 (회원별, 매일 9시)

```
후보 = 이번 주 모임 기도제목(미응답) + 나의 기도(미응답)
if 후보 있음:
    A: 후보 중 가장 오래전에 노출한 것(노출 이력 없으면 우선) 선택
elif 2주 이상 지난 미응답 모임 기도제목 있음:
    B-1 / B-2 를 하루씩 번갈아
else:
    B-2
제목 템플릿은 어제와 같은 것을 피해 로테이션
```

- "이번 주" = 모임 날짜(`gathering.date`) 기준 최근 7일
- 노출 이력/템플릿 이력은 `push_delivery_log`(`push_type = DAILY_PRAYER`, `entity_id`, `template_key`)에서 조회
- 진행 상황 표시("3개 중 2번째" 등)는 넣지 않음

### 문구

**A. 보여줄 기도제목이 있을 때** — 본문은 기도제목 원문, 클릭 시 기도 탭의 해당 기도제목으로 이동

| key | 제목 |
|---|---|
| PRAYER_A_1 | 오늘 이 기도로 하루를 열어요 🙏 |
| PRAYER_A_2 | 오늘도 이 마음을 올려드려요 |
| PRAYER_A_3 | 잠깐 멈추고 기도해요 🙏 |
| PRAYER_A_4 | 하나님께 다시 한번 맡겨요 |
| PRAYER_A_5 | 오늘 하루, 이 기도와 함께해요 |

**B-1. 예전 기도제목 다시 꺼내기** — 본문은 기도제목 원문, 클릭 시 해당 기도제목(응답 체크 가능)

| key | 제목 |
|---|---|
| PRAYER_B1_1 | {N}주 전 기도제목, 기억나세요? |
| PRAYER_B1_2 | 이 기도를 계속 이어가요 🙏 |
| PRAYER_B1_3 | 아직 기도하고 있는 제목이에요 |

**B-2. 새로 적어보기** — 클릭 시 나의 기도 작성 화면

| key | 제목 | 본문 |
|---|---|---|
| PRAYER_B2_1 | 이번 주 기도제목을 적어볼까요? ✍️ | 마음에 있는 것 하나만 적고 기도해요 |
| PRAYER_B2_2 | 요즘 어떤 마음이세요? | 짧게라도 기도제목으로 남겨봐요 |
| PRAYER_B2_3 | 오늘 감사한 일 하나 있나요? 🌿 | 감사도 기도가 돼요. 한 줄 적어봐요 |
| PRAYER_B2_4 | 함께 기도하고 싶은 사람이 있나요? | 가족, 친구를 위한 기도제목을 적어봐요 |
| PRAYER_B2_5 | 한 주를 기도로 시작해요 | 이번 주 기도제목을 적고 기도하러 가요 🙏 |

### 딥링크

- A, B-1: `/prayers?highlight={prayerId}` → 해당 항목 스크롤 + 강조
- B-2: `/prayers?write=1` → 작성 시트 자동 오픈

### 성능

현재는 구독자 전원에게 같은 payload. 개편 후 회원별 조회 필요 → 구독자 목록 기준으로 일괄 조회(기도제목, 최근 DAILY_PRAYER 로그)를 각 1~2회 쿼리로 가져와 메모리에서 조립 (N+1 금지). 인덱스: `prayer(member_id)` 기존, `push_delivery_log(member_id, push_type, sent_at)` 선행 작업에서 추가.

## 테스트

- 선택 로직 (단위): 후보 우선순위, 최소 노출 우선, B-1/B-2 교대, B-1 대상 없으면 B-2, 전날 템플릿 회피, 응답된 기도 제외
- 나의 기도 API: 본인 외 수정/삭제 불가, 모임 기도제목 내용 수정 불가
- 비공개: 어드민 회원 상세에서 나의 기도 미노출

## 구현 메모 (2026-11-26)

**Backend**
- `POST /prayers`(작성), `PATCH /prayers/{id}`(나의 기도 내용 수정) 추가
- 본인 확인: `updateAnswered`는 본인만, `delete`는 나의 기도만 본인 한정 (모임 기도제목은 리더가 모임 화면에서 지우므로 기존 동작 유지), `updateContent`는 본인 + 나의 기도만
- 기존 버그 수정: `PrayerPersistenceAdapter.toEntity`가 `visit_member_id`를 매핑하지 않아 저장 시 심방 연결이 지워질 수 있던 문제, `gathering_member_id`가 null이면 NPE 나던 문제
- 나의 기도 판별은 조인 결과가 아닌 FK(`prayer.gatheringMember.id`)로 — 소프트 삭제된 모임의 기도제목이 나의 기도로 잘못 분류되지 않도록
- `/prayers/me` 응답에 `source`(MY/GATHERING), 홈 요약에 `myPrayers`(최대 3) + `myPrayerCount`
- 기도 알림: `PrayerPushComposer`(순수 함수)가 회원별 내용 결정, `PushNotificationSendService`에서 후보 기도제목(`PrayerPort.findUnansweredForPush`)과 최근 60일 발송 이력(`PushDeliveryLogPort.findByMemberIdsAndTypeSince`)을 회원 전체 대상으로 각 1회 일괄 조회
  - B-1 대상 범위: 모임 날짜 14~90일 전 (조회도 90일로 제한)
  - 본문 100자 초과 시 말줄임
- 인덱스: `prayer(member_id)`, `push_delivery_log(member_id, push_type, sent_at)` 기존 인덱스로 충분 (추가 없음)

**Web-app**
- 기도 탭: `직접 쓰기` 버튼, 작성/수정 바텀시트(`MyPrayerSheet`, 200자, 삭제는 두 번 탭 확인), "내가 쓴 기도제목" 그룹, 딥링크 `?highlight=` / `?write=1` 처리 후 쿼리 제거
- 홈: `MyPrayerCard`(나의 기도), 이번 주 모임 기도제목/목표와 나의 기도가 모두 없을 때만 `MyPrayerEmptyCard`; 나의 한 주 카드의 기도제목 라벨을 "모임 기도제목" + 소그룹 이름으로
- 온보딩: 홈 요약 슬라이드에 나의 기도 추가, 기도 탭 "직접 쓰기" 슬라이드(`prayer-write`) 신설

**Admin**
- `lib/prayer.ts`의 `EXCLUDE_PERSONAL_PRAYER`로 회원 상세(API/페이지) 기도제목 히스토리에서 나의 기도 제외
- `PATCH/DELETE /api/prayers/[id]`: 다른 회원의 나의 기도는 403
